## Why

The TypeScript definitions generated by the inject-js and TypeScript generators were using positional parameters for methods with multiple parameters (e.g., `Actions.start(intent: string, handlerAppId?: string)`), which did not match the inject-js runtime's single object parameter pattern. Additionally, event callbacks lacked the two-parameter signature `(event, cancelled: boolean)` needed for cancellation support on connection failures. This misalignment made the TypeScript definitions inconsistent with the actual runtime behavior and reduced developer ergonomics.

## What Changes

- **BREAKING**: Updated TypeScript generators to use single object parameter pattern for all methods with parameters instead of positional parameters
- **BREAKING**: Changed event callback signatures from single parameter to two parameters with cancellation support `(event, cancelled: boolean)`
- **Added**: `Firebolt.Module` namespace organization for all type declarations and methods
- **Added**: JSDoc `@example` tags with realistic parameter values for all methods with parameters
- **Modified**: `src/generators/typescript.ts` to generate parameter interfaces with `ModuleMethodParams` naming convention
- **Modified**: `src/generators/inject-js-types.ts` to match the same parameter patterns and namespace organization
- **Added**: Export of `Firebolt` namespace in inject-js definitions for direct consumption
- **Fixed**: Metrics module parameter interfaces that were incorrectly using `params: string` instead of proper object structures

## Capabilities

### New Capabilities
None - this is a generator implementation change, not a spec-level capability change.

### Modified Capabilities
None - this change affects only generator implementation, not the Firebolt API specification.

## Impact

- **Breaking Change**: Existing TypeScript code using positional parameters will need to be updated to use object parameters. However, there are no current developers using this API, so the impact is minimal.
- **Generator Output**: All generated TypeScript definition files (.d.ts) will have new structure with `Firebolt.Module` namespace
- **Package Distribution**: The `@firebolt-js/types` package will include the updated definitions
- **Developer Experience**: Improved IDE support with JSDoc examples and better type safety through parameter interfaces
- **Runtime Compatibility**: No changes to runtime behavior - the inject-js runtime already supports the object parameter pattern
